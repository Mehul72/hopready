## Resume

```sh
cd ~/hopready
git switch feat/hopready-v1
# pnpm can stop at a prompt in automation; run it non-interactively.
CI=true pnpm install --frozen-lockfile --config.confirm-modules-purge=false < /dev/null
pnpm check                      # typecheck, lint, tests, format
pnpm --filter @hopready/api dev # local API on http://localhost:8787 (see apps/api/README.md)
cd apps/mobile && npx expo run:ios   # simulator development build (needs CocoaPods)
```

Live provider keys are read from the macOS Keychain (service `hopready`). See docs/OWNER-ACTIONS.md. The UI tests are in docs/testing.md.

## Known limitations

- **Live providers are checked, not exercised at scale.** The live checks pass against real TfNSW and Apple Maps, and the TfNSW parser is tested against two recorded trips, the car park list and one occupancy reading. The deployed API, and the app on live data, have not been tried yet (docs/testing.md).
- **The demo world** uses real stops but generated timetables. It shows the planner's rules hold, not what TfNSW will return (docs/testing.md).
- **Station entrances and exits** are never named. TfNSW may send details in fields HopReady does not read yet, so the timeline says they are not provided and to follow the station signs (docs/design/routing.md).
- **Services already left** cannot be checked again. Once a followed trip has started, only the services still to come are planned, so a delay on the service being ridden, and a connection it then misses, is not seen. The trip screen says so (docs/design/routing.md).
- **Fares and accessibility** are always shown as unknown. TfNSW removed Opal fares from the Trip Planner API in October 2023 (docs/design/routing.md).
- **Only five car parks per plan** get exact journeys, one per station. The rest are listed with an estimate from a hub table that is a timetable snapshot, re-recorded by hand, and rough for destinations far from any hub (docs/decisions/0007).
- **Walking the rest from a car park** is HopReady's estimate, timed like TfNSW's street walks (1.5 times the straight line at 1.1 m/s), not a routed path: a river or motorway between the car park and the destination makes it optimistic. It also ignores Dee Why's overnight closing (docs/decisions/0010).
- **On Demand services** that TfNSW returns as product class 10 are dropped by the adapter, so journeys using them are not offered (docs/research/park-and-ride.md 1.5).
- **Walking speed** is not sent to TfNSW, because no parameter for it has been verified; slow walkers get TfNSW's walking times stretched instead. The walking limit is sent as a preference, and marks options rather than hiding them (docs/decisions/0008).
- **Apple's drive times** have no published accuracy for Sydney; compare them with real drives before a public release (docs/release.md).
- **Apple-sourced places** (saved places, recent trips, the followed trip) are kept on the phone until deleted, which a strict reading of Apple's terms does not allow (owner decision 22).
- **Hermes** ships without its own privacy manifest, so App Store Connect may reject the first upload (docs/release.md).
- **Workers Free** may fail slow requests with Error 1102 and caps requests at 100,000 a day (docs/runbook.md). Workers Paid needs the owner's approval.
- **TfNSW's 5 requests a second** is enforced per Worker isolate only, so busy periods can exceed it across isolates (docs/providers.md).
- **One real-iPhone session so far** (2026-10-28, build 1): planning and following a trip on live data. GPS, Take me home, offline and VoiceOver on a device are still on the TestFlight checklist (docs/release.md).
